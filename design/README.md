# Reader — 设计文档

一个自用的电子书阅读器。视觉与交互参考 [Infinite Reader](https://ereader.space/)，核心目标是**在浏览器里复刻「书桌上的实体书」的阅读体验
**。

## 目标与非目标

### 目标

1. 打开一本 EPUB，看到一张书桌、一本摊开的书，双页跨页、固定分页、不能滚动。
2. 排版达到中文纸质书水准：两端对齐、首行缩进、避头尾、页眉页脚、章起于右页。
3. 阅读设置可调且**不丢阅读位置**：字体、字号、行距、页边距、桌面主题、环衬。
4. 可以高亮、下划线、贴便签，重新排版后标注位置依然准确。
5. 书籍、进度、标注持久化在服务端，换设备/换浏览器能接着读。

### 非目标（首版不做）

- PDF、MOBI、TXT 等其他格式（只支持 EPUB）。
- 多用户注册、登录、权限体系（自用，单用户）。
- AI 问答、思维导图、3D 图谱。
- 移动端单页重排（桌面优先，窄屏只做降级兜底）。
- 真 3D WebGL 书籍模型（列入可选阶段，见 [03-tasklist.md](03-tasklist.md) Phase 7）。

## 关键决策记录（ADR）

### ADR-001 前端 Vue 3，后端 Python FastAPI

- **决策**：前端 Vue 3 + TypeScript + Vite + Pinia + Vue Router；后端 FastAPI + SQLAlchemy + SQLite。
- **理由**：用户指定。前后端分离，阅读器能把「解析/排版」这类重计算放在前端，保证翻页零网络延迟；后端只负责文件与状态持久化，职责清晰。Vite
  的 HMR 迭代体验优于原站的技术组合对本项目的适配度。
- **代价**：原站的实现细节（React 19 + three.js）不能直接抄代码，只能抄**思路与数值**。

### ADR-002 分页用 CSS columns，不做逐字 canvas 排版

- **决策**：用 CSS `column-width` + 定高视口 + `translateX` 位移实现固定分页；页数由 `scrollWidth` 反推。
- **理由**：原站用 canvas 画字 + 透明 DOM 文字层，是为了让页面贴图能在 3D 中弯曲，代价是丢掉原生选区、可复制、无障碍，并要自己实现伪选区渲染。我们用
  DOM 直接排版，能拿到约 90% 的观感，工程量少一个数量级，且 Phase 7 上真 3D 前无需重写业务逻辑。
- **代价**：`break-before`
  、避头尾、图片断栏等细节由浏览器决定，跨浏览器行为需实测（见 [02-architecture.md](02-architecture.md) 风险表）。因此分页引擎必须是
  **可替换的隔离模块**。

### ADR-003 定位坐标 = 章节索引 + 字符偏移

- **决策**：全书统一为 `(chapter, charOffset)` 一维坐标。页码、进度、高亮、便签锚点全部由它派生，**任何地方都不许用页码或 DOM
  节点引用做持久化锚点**。
- **理由**：换字体、改字号、改窗口宽度都会导致重新分页，页码本身不稳定。字符偏移在重排后仍能通过 `Range`
  测量映射回新页码，这是「改设置不丢位置」的唯一可靠方案。
- **代价**：每次重排要做一次 Range 测量，需去抖并限制在可视范围内。

### ADR-004 首版就包含后端，服务端为权威数据源

- **决策**：书籍文件、元数据、阅读进度、批注全部走 FastAPI 落库；前端只做内存缓存与 IndexedDB 兜底，不做「先纯本地、后补后端」两套实现。
- **理由**：用户明确要求首版带后端。提前定好 API 契约，避免后面把 IndexedDB 模型硬迁到关系模型时返工。
- **代价**：Phase 1 依赖后端能跑起来，脚手架必须一次到位（见 03 的 Phase 0）。

### ADR-005 首版 2.5D CSS 拟真，3D 作为可选升级

- **决策**：用 CSS `perspective` + `rotateX` + 多层阴影 + SVG 纸纹模拟书桌与实体书；翻页用 CSS transform 过渡，不做卷曲。真
  3D 列入 Phase 7。
- **理由**：先让「能读、好读、像书」三件事成立，再谈视觉奇观。2.5D 阶段产出的 DOM 结构、坐标系统、批注层在升级 3D 时可全部复用。
- **代价**：无法实现原站的「纸背透字」和页角卷曲，静态截图相似度约 80%。

### ADR-006 只用 EPUB，单用户无登录

- **决策**：仅解析 `application/epub+zip`；不加注册登录，服务端通过可选的环境变量口令（`READER_TOKEN`）做最简保护，默认关闭。
- **理由**：项目定位是自用。账号体系会引入会话、密码、OAuth、找回密码等一整条与阅读无关的链路。
- **代价**：后续若要公网多用户使用，需要补认证层（ADR 可推翻，接口路径已预留 `/api/auth/*` 位置）。

## 待确认假设

以下几处是本轮推断，实现前若与预期不符需调整：

1. ~~示例书来源~~ **已确认**：中文用《呐喊》，英文用 *Alice's Adventures in Wonderland* 原文，均为公版。由
   `scripts/build_samples.py` 生成，产物为 `samples/nahan.epub`（15 篇 7.0 万字）与 `samples/alice.epub`（12 章 14.6 万字符，含第
   1 章 3 幅 Tenniel 插图）。文本源分别是维基文库（用 `Accept-Language: zh-hans` 由服务端转简体）与 Standard Ebooks 的
   GitHub 仓库；下载结果缓存在 `.cache/samples/`，可重复构建。
2. **章起于右页**：原站有此表现。CSS columns 下需要在章首插入 0~1 个空白列对齐奇偶，属视觉细节，Phase 3 再打磨。
3. **服务端是否需要解析 EPUB**：当前设计是后端用 Python 标准库 `zipfile` 只提取 container/opf
   的元数据与封面，完整解析在前端。若后续要在无浏览器环境导入书籍，再提升后端解析。
